02 / 05 O pipeline inteiro 0:20 – 1:10

Do CSV cru ao modelo, em quatro paradas

Cada camada tem uma responsabilidade só, e a contagem cai a cada passo — é essa queda que prova que houve trabalho de verdade no meio.

03 / 05 Por que Medallion 1:10 – 2:00

Cada camada resolve um problema que nós encontramos

Não é separação por convenção. Cada fronteira existe porque um problema concreto do VRA apareceu e precisou de um lugar para morar.

Bronzetb_anac_bronze

A fonte é instável.

Os 36 arquivos não têm o mesmo formato: a coluna Codeshare aparece a partir de out/2022, então 15 arquivos têm 21 colunas e 21 têm 20. As datas vêm em dois padrões e o encoding é ISO-8859-1. Guardando tudo cru e como texto, quando a fonte muda de novo só a Silver precisa mudar — a Bronze nunca é reingerida.

Silvertb_anac_silver

O dado bruto mente.

Há registros duplicados, voos cancelados misturados aos realizados e outliers impossíveis — o atraso mínimo era −1.453 min e o máximo +3.894 min, virada de data mal gravada. A Silver tipa, deduplica pela identidade natural da perna de voo e corta em ±24h. A limpeza mora num lugar só, em vez de repetida em cada consulta.

Gold..._gold_features_atraso

O modelo não pode ver o futuro.

É aqui que a fronteira do vazamento de alvo é desenhada: toda coluna que só existe depois da decolagem vira insumo do rótulo, nunca entrada. A Gold também marca o corte temporal de avaliação, para que treino e teste jamais se cruzem no tempo.

04 / 05 As features e a barreira 2:00 – 2:40

Dez colunas entram. Cinco não podem entrar nunca.

A tabela Gold tem quinze colunas, mas o modelo só pode enxergar dez — todas conhecidas antes de o avião sair do portão.

Features do contrato 10
sg_empresa_icao sg_icao_origem sg_icao_destino cd_tipo_linha sg_equipamento_icao nr_assentos_ofertados hora_partida_prevista duracao_prevista_min dia_semana mes

Todas derivam da programação do voo. É o que permite servir o mesmo modelo em tempo real no Trabalho Final, com um payload autocontido.

Barradas 5
atraso_partida_minutos faixa_atraso dt_referencia nr_voo dt_partida_prevista

As duas primeiras só existem depois da decolagem: se entrassem no vetor, o modelo aprenderia atrasou = atraso > 15 e devolveria AUC 1,0. As outras três são chave e rastreabilidade.

Por isso existem as duas views. Sem elas o CREATE MODEL precisaria de um SELECT * EXCEPT(...) — uma lista negra, cujo modo de falha é silencioso: basta alguém acrescentar uma coluna à Gold e esquecer de somá-la ao EXCEPT para ela virar feature sozinha, sem erro nenhum, só uma métrica boa demais. A view inverte para lista branca: enumera as dez, e SELECT * sobre ela não consegue ver mais nada. É a diferença entre lembrar de excluir e não ter como incluir.

05 / 05 Treinamento e placar 2:40 – 3:20

Um CREATE MODEL sobre a view de treino

SQL puro, sem sair do BigQuery. As opções que importam estão anotadas — cada uma responde a uma característica real da base. 

CREATE OR REPLACE MODEL
  `pdm-bia-2026.tf_anac.mdl_anac_m1_boosted_tree`
OPTIONS (
  MODEL_TYPE       = 'BOOSTED_TREE_CLASSIFIER',  -- exporta p/ Vertex
  INPUT_LABEL_COLS = ['atrasou'],
  AUTO_CLASS_WEIGHTS = TRUE,                -- só 17,1% atrasam
  CATEGORY_ENCODING_METHOD = 'LABEL_ENCODING', -- 175 aeroportos
  MAX_ITERATIONS   = 50,
  MAX_TREE_DEPTH   = 8,
  LEARN_RATE       = 0.1,
  ENABLE_GLOBAL_EXPLAIN = TRUE             -- SHAP nativo
) AS
SELECT * FROM `...vw_anac_gold_treino_m1`;

O achado: a meta era AUC ≥ 0,70 e não chegamos. As dez features descrevem só a programação do voo — falta o estado do dia: meteorologia, rotação da aeronave, atraso acumulado da malha. O baseline existe justamente para dar tamanho ao número: sem ele, 0,66 não significaria nada.
