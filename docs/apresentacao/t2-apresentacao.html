Ingestão em tempo real e deploy do modelo

Predição de atraso de voos com meteorologia em streaming

Observações meteorológicas dos aeroportos entram em tempo real por Pub/Sub e Dataflow até o BigQuery. O modelo de atraso é servido por uma API no Cloud Run, que consulta o endpoint do Vertex AI.

Motivação

O modelo do T1 só via o voo, mas o clima também atrasa voos

No T1 o modelo usava apenas dados do voo: companhia, rota, aeronave, horário e calendário. Com isso, a AUC ficou em 0,65, abaixo da meta de 0,70. Faltava uma causa conhecida de atraso: as condições do clima no aeroporto de origem.

Parte A

Ingestão em tempo real

De onde vêm os eventos, como cada mensagem é validada e o que acontece com as que violam o contrato.

A1 Fonte dos eventos

O clima no aeroporto muda de hora em hora, e cada mudança vira um evento

Voos · VRA/ANAC
  • Publicados uma vez por mês, depois que os voos acontecem.
  • Processados em batch, na arquitetura Medallion do T1.
Meteorologia · METAR
  • Boletim que cada aeroporto emite a cada hora, com vento, visibilidade, nuvens e fenômenos como chuva e trovoada.
  • Cobre 65 dos 100 aeroportos de origem, que somam 92,9% dos voos.

A2 Pipeline de ingestão

Pub/Sub → Dataflow → BigQuery, com dead-letter

Pub/Sub
  • Tópico anac-metar, retenção de 1 dia.
  • Assinatura pull lida pelo Dataflow.
Dataflow
  • Apache Beam em modo streaming, Streaming Engine.
  • 1 a 2 workers e2-standard-2.
  • Valida tipo, faixa e domínio pelo contrato.
BigQuery e dead-letter
  • Streaming inserts, partição diária, cluster por aeroporto.
  • Inválidas vão para anac-metar-dlq com o motivo.

O dead-letter é feito dentro do pipeline. Campos fora do contrato são recusados, o que impede que um dado posterior à partida chegue à tabela.

Parte B

Arquitetura de deploy da API do modelo

Como o modelo treinado no BigQuery ML chega a um endpoint, e como a API no Cloud Run atende uma requisição.

B1 Do treino ao endpoint

O modelo vai do BigQuery ML ao Vertex AI sem exportar arquivo

Registro do modelo
  • MODEL_REGISTRY = 'VERTEX_AI' no próprio CREATE MODEL.
  • O endpoint serve o modelo vigente no BigQuery, sem cópia.
Imagem da API
  • python:3.12-slim, usuário sem privilégio.
  • Leva o contrato junto: API e modelo não divergem.
Cloud Run
  • 1 vCPU, 512 MiB, até 3 instâncias.
  • Escala a zero fora da demo; 1 instância quente na apresentação.
  • Sem acesso anônimo.
B2 Caminho de uma requisição

Da chamada à probabilidade de atraso

  1. O cliente envia o voo e o clima da origem, com token de identidade. Sem token: HTTP 403.
  2. A API valida o payload contra o contrato. Campo fora do contrato ou valor inválido: HTTP 422.
  3. Campos de clima ausentes recebem a média do treino, o mesmo tratamento do BigQuery ML.
  4. A API chama o endpoint do Vertex e devolve a probabilidade de atraso acima de 15 min.
  5. Depois da resposta, a predição é gravada no BigQuery para comparar com o resultado real.
